# Anglerfish-AI Whole-Project Code Review

## Overall read

The codebase is in good structural health. The architecture is coherent (event-sourced audit log feeding a tailer that hydrates a session store, a bridge that fronts a local LLM, a deception lure), the type and coverage discipline is real, and most defects are contained by the single-operator threat model rather than amplified by it. The dominant theme is doc-drift and half-wired features: docstrings that describe behavior the code does not implement (static honeytokens, fs_context, the LLM classifier pass, JA3 wiring, the threat scoring pipeline, the embed-role integrity check), and feature plumbing that exists on one side of an interface but has no producer or consumer on the other. The second recurring smell is contract-vs-implementation gaps in error handling: several "never raises" / "degrades to None" promises are false because the catch is too narrow or absent (geo lookup, geo fetch, persistence classifier). The third is the deception-fidelity class of bugs, where small inconsistencies (stale cwd, ls -l sizes of 0, cd - handling, fixed inter-chunk delays) act as honeypot tells. Test gaps cluster precisely on the production paths and failure branches that integration never exercises (owned-reader lifecycles, rotation failure recovery, the false-positive technique-matching path). The genuinely material correctness bugs are few: the restart-induced command drop, the technique false positives, and the streaming budget-lock leak are the ones that touch the system's core mission.

Note on severity: each finding was adversarially re-verified, and several originally-labeled "high" items were downgraded in deployment context. Grouping below reflects the verified severity.

## Findings by severity

### High

**Commands dropped after dashboard restart (`dashboard/state.py:169`).** `update_session` computes new turns by positional slice (`snapshot.turns[len(existing_turns):]`), but the tailer's accumulator starts empty after restart and is never rehydrated from the store, so a command on a pre-restart-open session diffs to `()` and is silently lost while the SPA regresses to a 1-turn view. Fix: rehydrate the accumulator from `get_session` on cache-miss, or diff turns by sequence/identity instead of slice position.

**Argument patterns match across unrelated commands (`threat/techniques.py:67`).** `matches()` tests `argument_patterns` independently of the command head, so `apt install`, `pip install`, `make install` all trip T1543 (persistence) and `git show` trips T1016. This sets `persistence_attempted=True`, adds the +20 bonus, and forces `high_severity`, corrupting the signal that gates engagement and honeytoken placement. Fix: only test `argument_patterns` when `head in self.commands`.

**T1098 flips persistence on read-only credential-file access (`threat/techniques.py:223`).** The pattern `authorized_keys|/etc/sudoers|/etc/shadow` matches regardless of verb, so `cat /etc/shadow` and `grep root /etc/sudoers` set `persistence_attempted=True` and fire an alert. Fix: require a write/edit indicator, or drop `/etc/shadow` from T1098 since T1003 already covers reads. (Same root cause as the entry above: persistence flags are over-broad because pattern matching ignores command context.)

**Static-base honeytoken feature has a full read path but no producer (`honeytokens/schema.py:140`, `config/models.py:1085`).** `is_static_base()`, `list_static_honeytokens` (WHERE source_ip IS NULL), the bridge merge, and the `static_base_paths` config field are all built and documented as shipping, but no code ever generates a token with `source_ip=None`, so the entire read chain and config field are dead and the docstring guarantee is false. Two sites, one feature. Fix: ship the startup seeding routine that reads `static_base_paths` and registers `source_ip=None` tokens, or delete the plumbing and the docstrings that claim it works.

**`stream_chat` holds the per-session budget lock across a caller-controlled loop (`llm/client.py:271`).** The async generator yields inside `async with budget.lock`, so the bridge's early `break` (service.py:1308) suspends the generator with the lock held; the next command on the same session deadlocks on the reused per-session lock. Reproduced. Fix: do not hold an `asyncio.Lock` across unbounded iteration. Reserve projected tokens under the lock before streaming and reconcile at the end, or restructure so release runs on `GeneratorExit`.

**`fetch_geolite_databases` lets httpx/parse errors escape its FetchError-only contract (`geo/fetch.py:144`).** `raise_for_status()`, connect/read timeouts, and an empty-manifest `IndexError` all propagate uncaught past the CLI's FetchError-only handler, crashing `anglerfish geo update` with a traceback and skipping the `geo.update_failed` audit record (the operator's only failure signal under the systemd timer). Fix: wrap the network + parse work to convert `httpx.HTTPError` and the empty-manifest case into `FetchError`.

**`GeoLookup.lookup()` catch is too narrow for its "never raises" contract (`geo/lookup.py:105`).** `_lookup_one` catches only `(ValueError, OSError)`, but a corrupt MMDB raises `maxminddb.InvalidDatabaseError`, which subclasses `RuntimeError` and propagates out of `lookup()`. Fix: broaden the catch to include `RuntimeError` or catch `maxminddb.InvalidDatabaseError` explicitly.

### Medium

**Bridge-reported cwd is never applied to the lure session (`lure/server.py:753`).** The bridge tracks cwd and returns it on every chunk/response, but `_handle_bridge_stream` reads only `chunk.delta` and `submit_command` discards cwd, so a bridge-handled `cd /tmp && ls` leaves the lure's prompt and native pwd/cat/ls resolving against a stale directory. Fix: have `submit_command` return cwd and call `session.update_cwd(...)` from the terminal chunk/response.

**Lure sends `fs_context` on every command but the bridge discards it (`bridge/server.py:414`).** The lure computes `system_prompt_summary` and ships up to 4 KB per request; `CommandRequest` validates `fs_context` and the docstring claims the prompt builder uses it, but the endpoint never reads `req.fs_context` and the prompt builders take no such parameter. Fix: thread `fs_context` into the prompt builders, or delete the field and the client/lure/docstring references.

**Multiple exec channels on one connection leak all but the last bridge session (`lure/server.py:383`).** `_process_handler` overwrites `state.bridge_uuid` per channel; `connection_lost` closes only the last one, orphaning the rest until idle eviction. Fix: track all opened `bridge_uuid`s on `_ConnectionState` and close each.

**`_join_commands` embeds empty text when the newest command exceeds `max_command_chars` (`intel/embeddings.py:160`).** A single over-cap command breaks the loop on the first iteration and returns `""`; `generate()` does not guard, so it calls `embed("")` and persists a meaningless behavioral vector. Fix: fall back to the newest command truncated to cap, or short-circuit `generate()` when the join is empty.

**`get_intents_in_range` skips the bounds-check and result cap its sibling enforces (`sessions/store.py:490`).** Unlike `get_sessions_in_range`, it takes no limit, applies no LIMIT, and silently returns empty on an inverted range. Same asymmetry in `_gather_export_window` (routes.py:277). Currently protected only by the route's 7-day cap. Fix: mirror the sibling's `end < start` validation and `limit` bound.

**`find_similar` docstring claims "newest-first" but sorts purely by similarity (`sessions/store.py:1104`).** `generated_at` is fetched but never used in the sort; ties fall in arbitrary scan order. Fix: rewrite to "highest-similarity first," or add `generated_at` as a documented secondary key.

**Wizard accepts a remote-Ollama config the runtime validator rejects (`wizard/wizard.py:362`).** The wizard prompts for a "Trusted remote Ollama IP (must match endpoint host)" but never enforces it: a hostname endpoint or a mismatched IP is accepted and written, then `OllamaConfig._validate_endpoint_host` rejects it at first boot. Fix: mirror the OllamaConfig host rules in the wizard (parse with `ipaddress.ip_address`, verify the trusted IP equals the endpoint host).

**`/api/clusters` N+1 defeats the single-scan graph API (`dashboard/routes.py:530`).** After `get_cluster_graph` returns the whole graph in one scan, the route issues `get_session` + `get_intent` per node (up to 2000 lock-serialized SQLite hops at the 1000-node cap), and `get_session` reloads every turn though only source_ip/persona are used. Fix: batch the metadata via ranged queries (the store already has `get_intents_in_range`) and build nodes from the maps.

**Tor refresh branch lacks the double-checked guard (`fingerprint/tor.py:88`).** The initial-load branch re-checks under the lock; the interval/mtime refresh branch does not, so a connection burst makes every in-flight coroutine run a full reload. Fix: re-test `interval_due`/`_mtime_changed()` after acquiring the lock and return early if another waiter already reloaded.

**`ls -l` shows size 0 for files `cat` returns content for (`lure/fakefs.py:509`).** `/etc/passwd` is `FakeEntry(..., 0)` with a "size computed at read time" comment that describes logic that does not exist; `ls -l` renders the literal 0 while `cat` returns 511 bytes. A direct fingerprint tell. Fix: compute size from rendered content, or drop the comment and hardcode plausible non-zero sizes.

### Low

**Wasting strategies return an identical inter-chunk delay for every chunk (`bridge/strategies/light.py:71`, `aggressive.py:104`).** The RNG is reseeded per `(session_id, command_count)` and drawn once, so every chunk in a command gets the same delay. A fixed cadence is a cleaner fingerprint than jitter, the opposite of the stated goal. Fix: reuse one `Random` per command across chunks, or fold a chunk index into the seed.

**`_handle_cd` mishandles `cd -` and tilde-user forms (`bridge/service.py:1661`).** `cd -` joins to `<cwd>/-`, `cd ~user` to `<cwd>/~user`, producing visibly wrong prompt paths. Fix: special-case `cd -` (track OLDPWD), expand leading `~`/`~user`.

**`structured_chat` stashes bad output only on ValidationError, not on invalid JSON (`llm/client.py:425`).** The more common failure for a small local model (non-JSON) never feeds the offending output back into context, weakening self-correction exactly where most needed and contradicting the stated intent. Fix: append the assistant reply in the JSONDecodeError branch too.

**`health._wasting_stats` scans the whole audit log instead of breaking at the cutoff (`dashboard/health.py:237`).** Uses `continue` where its sibling `_command_rate_per_minute` uses `break` on `ts < cutoff`. Fix: split the condition (`ts is None: continue`, `ts < cutoff: break`).

**`/api/threats` advertises limit up to 500 but the facade caps at 200 (`dashboard/state.py:433`).** A request for 201-500 silently returns at most 200 with no truncation signal. Fix: align the route cap to 200 or raise the facade default to 500.

**`_suppress_get_nowait` returns a context manager from inside a suppress block (`dashboard/state.py:472`).** A convoluted helper whose `QueueEmpty` branch can let a re-raised `QueueFull` abort fan-out (unreachable today in single-threaded asyncio). Fix: inline two flat `contextlib.suppress` blocks in `publish`.

**`systemctl` unit names with `-` or `.` are truncated to the first segment (`persistence/patterns.py:210`).** The lazy `(\S+?)` plus `\b` stops at the first non-word char, so `systemctl enable my-backdoor.service` records `sub_key='my'`, breaking later status-replay lookups. Fix: capture greedily and strip an optional `.service` suffix afterward.

**Oversized regex capture raises ValidationError past the classifier's graceful-miss contract (`persistence/patterns.py:305`).** Extractors build `PersistenceEvent` from unbounded captures; above the default `max_input_chars` (operator-configurable to 32768) a long payload/sub_key raises uncaught. Coincidentally safe only at the default. Fix: truncate captures to the field bounds before construction, or wrap the regex pass in `try/except (ValueError, ValidationError)` returning None.

**Username trimming inconsistent between `begin_auth` and `validate_password` (`lure/server.py:445`).** `begin_auth` stores `username[:64] or 'root'`; `validate_password` records the raw username un-trimmed, so one connection can present two usernames across records. Fix: reuse `state.username` (or a shared helper) in `validate_password`.

**`BridgeStreamChunk.done`/`.cwd` parsed and tested but unused (`lure/bridge_client.py:437`).** The protocol shape shipped, the consumer half did not; ties into the cwd-drift finding. **`StrategyContext.command`/`wasted_ms_so_far` set on every command but read by no strategy (`bridge/strategies/base.py:51`).** Dead context fields with a misleading docstring. **`FakeEntry.mtime` threaded but never rendered (`lure/commands.py:289`)**; `ls -l` hardcodes `May 23 14:01`. Fix each: wire the field through or remove it and correct the docstring.

**Several declared-but-never-raised / never-called API surfaces.** `IntentExtractionError`/`EmbeddingExtractionError` are exported but never raised, with docstrings asserting a bridge contract that does not exist (`intel/intent.py:107`, `embeddings.py:55`). The `logger` param and `self._logger` are stored but never used in both intel producers (`embeddings.py:98`, `intent.py:174`). `score_session`/`ThreatEngine`/`ThreatAlerter` have no live caller and `record_threat_assessment` has no production caller (`threat/service.py:57`). `PersonaRegistry.get_or_default` has no production caller and a false "used by the selector" docstring (`persona/registry.py:119`). `_utcnow()` is dead in the read-only reader (`sessions/reader.py:307`). The unused `_logger` in `persona/selector.py:42`. `GeoLookup`/`GeoRecord` and `Fingerprinter.fingerprint`/JA3 surface have no production consumer (`geo/lookup.py:40`, `fingerprint/service.py:69`). `AuditLog`'s context-manager methods are dead in production (`audit.py:154`). Fix: delete or mark each as a deliberate, currently-unwired extension point.

**Embedding/intent token budgets are hardcoded and unreachable from config (`cli/__main__.py:206`).** `IntentExtractor`/`EmbeddingGenerator` are constructed bare, so `session_deep_token_cap`/`session_embed_token_cap` have no effect, and the latter's description falsely claims it governs the generator. The `PersistenceClassifier` two lines later threads its cap correctly. Fix: add `intent_token_cap`/`embedding_token_cap` config fields and thread them; at minimum fix the false description.

**`data_dir` is a half-wired base-directory abstraction (`config/settings.py:72`).** Consumed only by the audit-tailer offset cache; the three real storage paths embed `/var/lib/anglerfish` independently, so `ANGLERFISH_DATA_DIR` moves only the offset cache. Fix: derive sub-config paths from `data_dir` in a root validator, or drop the field and key the tailer off `audit.log_path` like the others.

**Literal value sets duplicated as hand-maintained frozensets (`models/intent.py:25`).** The audit-tailer re-declares ActorProfile/IntentConfidence/PersistenceKind/PersistenceSource membership by hand; a new Literal member would be silently dropped with only a warning. Fix: expose `frozenset(get_args(...))` from the model module and import it.

**Duplication and drift across the reader/store facades.** `_row_to_honeytoken` is duplicated and has already drifted (str-coercion and a `type: ignore` on one side only) despite "lock-step" docstrings (`sessions/reader.py:311`). The same persistence query has two different method names across facades (`list_persistence_for_source_ip` vs `list_persistence_events_for_source_ip`, `sessions/reader.py:181`). `_DEFAULT_SCAN_MAX_CHARS` is coupled to the config default only by a comment (`bridge/defense.py:91`). AWS and SSH callback-URL builders are byte-identical (`honeytokens/generators.py:161`). The `_SCHEMA` constant is duplicated between rotation and storage. `RotationResult.new_path` holds the live DB path, not the `.new` work file (`credentials/rotation.py:203`). Fix: hoist shared code to one location, align names, and rename the misleading field.

**`load_settings()` + ValidationError->panel->Exit(2) duplicated verbatim eight times (`cli/__main__.py:112`).** Drift has already begun (one site uses `Console()` inline). Fix: extract `_load_settings_or_exit(console)`.

**Stale/incorrect docstrings and comments (doc-drift cluster).** `_parse_usage` claims usage is "parsed and discarded" though the budget machinery now consumes it (`llm/client.py:593`). The persistence classifier and `honeytokens/__init__` describe shipped work as future ("lands in slice 10.3", "Slice 11.1 ships only") (`persistence/classifier.py:18`, `honeytokens/__init__.py:9`). Placement docstrings mislabel session-keyed dedup as "per-source-IP" (`honeytokens/placement.py:13`, `bridge/service.py:385`). The bridge-serve comment claims the integrity check walks every LLM role and pins EMBED; it pins only fast/deep (`cli/__main__.py:168`). `intent.py:9` says "Two short-circuit cases" but lists one. The `embedding.py` docstring credits the model cross-check with DB-read truncation protection that `_unpack_vector` actually provides (`models/embedding.py:33`). The `select()` docstring describes a `get_or_default`/stale-pin-logging mechanism that does not exist (`persona/selector.py:80`). The `_hash_select` modulo-bias comment is mathematically wrong (`persona/selector.py:117`). The sshkey docstring claims only ED25519/RSA are accepted though ECDSA and sk-* are too (`wizard/sshkey.py:8`). The audit.py docstring understates which events the tailer consumes (`audit.py:67`). The fingerprint `__init__` claims the lure calls `compute_ja3`; it never does (`fingerprint/__init__.py:10`). The tarfile `filter="data"` comment wrongly calls it a no-op on 3.11 (`geo/fetch.py:216`). The legacy `model=`/`model_expected_hash=` shims carry a stale "removed after one cycle" promise and the install docs still teach the deprecated keys (`config/models.py:234`). Fix: correct each to present-tense reality.

**Models package surface inconsistencies (low-risk API).** `models/__init__.__all__` and `models.__all__` disagree with each other and with the defined types; production code bypasses the root facade entirely (`models/__init__.py:26`, `:4`). `source_ip`/`ip` field constraints diverge across models with no shared convention (`models/credentials.py:17`). `NarratorConfig.model_role` re-declares the role vocabulary as a Literal instead of reusing `LLMRole`, forcing a manual translation in narrator.py (`config/models.py:1248`). Honeytokens/CounterDeception configs raise from `model_post_init` instead of the `@model_validator` idiom used everywhere else (`config/models.py:1100`). `config/__init__.__all__` omits three names `models.__all__` exports (`config/__init__.py:26`). Fix: pick one convention per case and enforce it.

**`FetchResult.bytes_written` reports compressed download size, not on-disk size (`geo/fetch.py:186`).** ~30 MB reported for a ~70 MB installed City db, printed next to the destination path. Fix: report `destination.stat().st_size`.

**Callback reject path reflects unescaped attacker input into AWS XML (`callback/routes.py:121`).** `/cb/%3Cscript%3E` yields malformed XML (not RCE; no format-string injection), a fidelity tell that real AWS never produces. The hit/unknown paths are safe (base32-validated). Fix: return a constant placeholder body on the reject path, or XML-escape. **`request_path` audited field is redundant with `token_id` on this single-route receiver (`callback/routes.py:126`).** Fix: drop it or comment that it is always `/cb/<token_id>`.

**Audit-log correctness/hardening (low, latent).** `ts` is stamped outside the lock so it can diverge from physical append order, contradicting the in-order tamper-evidence claim (`audit.py:114`). A caller passing `ts=`/`event_type=` in `**fields` silently clobbers the canonical fields via last-write-wins `update` (`audit.py:117`; note `event_type=` actually raises TypeError, only `ts=` is exploitable). Fix: build the record dict inside the lock and set canonical keys last (or reject reserved keys).

### Test gaps (severity as verified)

- **Threat (`test_techniques.py:43`):** every argument-pattern test uses rules where the command head also matches, so the cross-command false-positive path is never exercised and the parametrized table only asserts membership, not the exact id set. Add a negative assertion (`commands=('systemctl',)`, assert `matches('apt install vim') is False`).
- **Credentials (`rotation.py:178`):** the `sqlite3.Error` cleanup and `OSError` swap-failure branches are entirely untested. **Crypto (`crypto.py:89`):** the non-UTF-8 `decrypt()` branch that callers rely on for skipping mixed-key rows is uncovered.
- **Callback (`app.py:48`):** the production lifespan path (`owns_reader` open/close + default AuditLog) is never run; only injected-reader tests exist. **CLI (`cli/__main__.py:482`):** the callback-serve disabled-honeytokens guard has no test and a whole-function `# pragma: no cover`.
- **Config:** `HoneytokensConfig(enabled=True)` without `callback_base_url` has no negative test (`config/models.py:1100`); `_validate_password_hash` rejection branch is uncovered and the length bound (`>= 59`) is looser than bcrypt's 60 (`config/models.py:356`).
- **Models (`tests/models/test_credentials.py:1`):** no co-located test for `embedding.py`, the one module with real runtime behavior; its raise branch is covered only via a consumer subsystem's suite.
- **Persistence (`test_patterns.py:154`):** no test for oversized-payload or hyphenated-unit-name behavior; the systemd test uses a single-segment name that masks the truncation.
- **Persona (`test_selector.py:218`):** no test combines a stale pin with a valid recurrence to lock in the fall-through ordering.
- **Fingerprint (`test_hashes.py:52`):** the HASSH UTF-8 path is asserted against ASCII encoding and the non-ASCII test checks only length/hex, so the H3 hardening is unpinned.
- **Wizard (`test_wizard.py:207`):** the only preflight test uses an override-and-ignore stub whose kwargs fall into `**_kwargs` and are discarded, so the wizard->checker plumbing is untested; it also carries a stale `_splunk_hec_url` param.
- **Geo (`lookup.py:182`):** owned-reader open/close, the default HTTP client branch, the `_MAX_BYTES` ceiling, and HTTP-error/network-failure paths are all untested while the 90% gate passes on disabled-path branches.
- **Core (`test_audit.py:93`):** no concurrent-`record()` test despite the advertised thread-safety contract; `test_record_fsyncs` asserts nothing about fsync; no reserved-key clobber test.

## Per-package notes

- **dashboard:** Core data path is sound but carries the single most material correctness bug (restart command drop) plus an N+1 on the cluster endpoint, an off-by-cap on `/api/threats`, and a convoluted backpressure helper.
- **threat:** Scoring model is well-structured, but two over-broad technique-matching bugs corrupt the `persistence_attempted` signal, and the scoring-to-alerting pipeline is orphaned with no live caller.
- **honeytokens:** Generation and per-session placement work, but the static-base feature is half-shipped (read path with no producer) and dedup docstrings mislabel session-keyed as per-source-IP.
- **geo:** Fetcher is live but violates its FetchError-only and "never raises" contracts in multiple places; the entire lookup half has no production consumer and the under-tested production branches are the risky ones.
- **bridge:** Solid command handling, but `fs_context` is dead end-to-end, the streaming budget lock can deadlock a session, wasting jitter is fixed-cadence, and several StrategyContext fields are unread.
- **lure:** Functional deception layer undermined by fidelity tells (stale cwd, ls -l size 0, cd - handling) and a multi-channel session leak; cwd-sync protocol fields are parsed but unconsumed.
- **llm:** Budget machinery is wired, but the streaming lock spans a caller-controlled loop, the JSON-retry path is asymmetric, and one usage docstring is stale.
- **persistence:** Regex extraction is the weak spot: oversized captures raise past the graceful-miss contract and hyphenated unit names truncate; classifier docstrings frame shipped LLM work as future.
- **credentials:** Rotation logic is correct on the happy path but leaves stale WAL sidecars that can revert the new DB after a crash, and the failure-recovery branches are untested.
- **intel:** Producers work, but token budgets are unreachable from config (with a false description), and the public extraction-error classes plus injected loggers are dead.
- **sessions:** Store/reader facades are clean but riddled with duplication, name drift, an unbounded `get_intents_in_range`, an O(n^2) cluster graph that cannot serve its advertised limit, and a "newest-first" docstring that sorts by similarity.
- **fingerprint:** HASSH path is correct; Tor refresh lacks a double-checked guard and pays an unconditional stat per call; the full fingerprint compose path and JA3 surface have no consumer.
- **wizard:** Usable but accepts remote-Ollama configs the runtime rejects, omits `/etc/hosts` from its output/audit, and its only preflight test asserts nothing about plumbing.
- **callback:** Receiver is correct on validated paths; the reject path reflects unescaped input into XML (fidelity tell, not RCE) and the production lifespan path is untested.
- **config:** Validation is thorough but `data_dir` governs almost nothing, two validation idioms coexist, several docstrings/`__all__` lists have drifted, and legacy shims overstay a "one-cycle" promise.
- **models:** Schemas are clean; the package facade is incomplete and bypassed, Literal sets are hand-copied into the tailer, and several docstrings enumerate stale type subsets.
- **persona:** Selection logic is correct but documented around a `get_or_default`/stale-pin-logging mechanism that does not exist; dead method, dead logger, and a wrong modulo-bias comment.
- **core (audit):** The append-only design is solid; `ts` is stamped outside the lock, reserved keys can clobber canonical fields, the context manager is dead, and the thread-safety and fsync contracts are untested.

## Recommended next actions

1. **Fix the restart command-drop (`dashboard/state.py:169`).** This silently loses attacker commands, the system's primary mission data. Rehydrate the accumulator on cache-miss and add the regression test that opens a session, advances the offset, builds a fresh tailer, and asserts the new turn persists.
2. **Scope `argument_patterns` to matched command heads and tighten T1098 (`threat/techniques.py:67`, `:223`), with the negative tests.** This corrupts the `persistence_attempted` signal that gates engagement and honeytoken placement; both fixes plus the missing negative assertion close it cleanly.
3. **Break the streaming budget-lock leak (`llm/client.py:271`).** Reserve projected tokens under the lock before streaming and reconcile after, so a consumer `break` cannot deadlock the next command in the session.
4. **Make the geo contracts true (`geo/fetch.py:144`, `geo/lookup.py:105`).** Convert httpx/parse errors to `FetchError` and broaden the lookup catch to `RuntimeError`, then add the HTTP-error and corrupt-MMDB tests. This restores the operator's only failure signal for the timer-driven update.
5. **Resolve the static-honeytoken half-feature (`honeytokens/schema.py:140`, `config/models.py:1085`).** Ship the seeding producer or delete the read chain, config field, and the docstrings that claim it works, so operators are not relying on guaranteed lure coverage that never lands.
6. **Fix the rotation WAL-sidecar revert (`credentials/rotation.py:188`) and add the failure-recovery tests (`:178`).** Checkpoint/`journal_mode=DELETE` the old DB before reading and relocate the `-wal`/`-shm` sidecars on swap, so an unclean shutdown cannot silently revert credential-intelligence data.
